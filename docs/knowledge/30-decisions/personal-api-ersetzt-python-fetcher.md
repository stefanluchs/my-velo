# Personal API ersetzt den Python-Fetcher (E7)

**Claim:** Seit 0.6.0 gleicht my Velo Garmin Connect über die offizielle Garmin Connect Personal API mit einem persönlichen API-Schlüssel ab, in reinem Go und ohne Passwort oder MFA.

## Kontext
Die Personal API (seit Oktober 2026) liefert dieselben Aktivitäts-IDs und dieselben
Original-FIT-Dateien wie der inoffizielle Weg, siehe [[personal-api-token-und-endpunkte]].

## Entscheidung
E7 im Register `docs/plan.md` §9: Go-Client `internal/garmin` statt Python-Subprozess.
Der FIT-Import bleibt Basis ([[fit-import-als-basis-ohne-weitere-plattform]]).

## Treiber
- Vorgesehene, stabile Nutzung statt Bot-Umgehung; kein Risiko einer Kontosperre.
- Python entfällt: Image von etwa 100 MB auf 27,5 MB.

## Verworfene Alternativen
- **Python-Fetcher beibehalten:** Passwort/MFA, Bruchgefahr bei jeder Auth-Änderung,
  native Abhängigkeit `curl_cffi`.

## Konsequenzen
- Der Schlüssel läuft nach 30–365 Tagen ab; der Nutzer muss ihn erneuern
  ([[personal-api-schluessel]]).

## Belege
- `docs/spikes/s4-personal-api.md` — Vergleich und Live-Test
- `my_velo/CHANGELOG.md` — 0.6.0
- `internal/garmin/client.go` — Go-Client

## Auswirkung auf die Implementierung
- Keine Python- oder CGO-Abhängigkeiten wieder einführen ([[aarch64-build-ohne-qemu]]).
