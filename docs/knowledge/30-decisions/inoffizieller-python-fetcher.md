# Garmin-Sync über inoffiziellen Python-Fetcher (bis 0.5.x)

**Claim:** Bis Version 0.5.x holte ein Python-Subprozess `garmin-fetch` auf Basis von `python-garminconnect` die Original-FIT-Dateien mit Benutzername, Passwort und MFA; dieser Weg ist durch die Personal API abgelöst.

> **Superseded** am 2026-10-23 durch [[personal-api-ersetzt-python-fetcher]].

## Kontext
Garmin hatte 2025/26 den Login-Ablauf geändert; `garth` wurde eingestellt. Gepflegt war nur
noch `python-garminconnect`, das sich mit `curl_cffi` (Browser-TLS-Fingerprint) wie ein Browser
verhält.

## Entscheidung
Subprozess statt Go-Client; MFA in **einem** Prozess, weil Garmin den MFA-Zustand nur im
Speicher der laufenden Anmeldung hält.

## Treiber
- Automatischer Abgleich ohne Zugang zum Developer Program.

## Verworfene Alternativen
- **`garth`:** eingestellt nach der Auth-Änderung.
- **Go-Client `abrander/garmin-connect`:** archiviert, kein gepflegter Go-Weg nach der
  Auth-Änderung.

## Konsequenzen
- Image etwa 100 MB (Python-Laufzeit), Passwort/MFA im Panel, Risiko einer Kontosperre.

## Belege
- `docs/spikes/s1-garmin-fetch.md` — Befunde zu Login, MFA, Image-Größe
- `my_velo/CHANGELOG.md` — 0.6.0 entfernt Python

## Auswirkung auf die Implementierung
- Nur noch historisch; kein Python-Code mehr im Repository.
